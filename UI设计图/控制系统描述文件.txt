智能环境控制系统描述文档
一、项目背景与目标
本项目构建端到端智能环境控制系统，实现底层设备数据采集、边缘计算控制、云端运维管理、移动端用户服务全链路闭环。核心目标：实现多协议设备统一接入与管理，提供云边协同的控制逻辑下发能力，为用户提供极简交互体验及耗材服务闭环。
二、系统架构要求
系统遵循 App - 云平台 - 边缘网关 - 终端设备四层架构。通信机制：支持双通道通信。广域网：App <-> 云端 <-> 网关（MQTT/HTTP）。局域网：App <-> 网关，支持本地发现与直连控制，确保断网可用。云端部署：有人云 / Jetlinks 私有化部署。硬件连接：家庭总网关、RS485 信号带 485 设备自主接入。
三、功能需求详情
（一）移动端（App/Pad）- iOS & Android
设计原则：极简 UI，统一交互，响应迅速。
连接与配网：局域网直连，无外网时 App 可在局域网内自动发现网关并控制。
设备控制：统一面板，屏蔽底层协议差异，同类设备使用统一 UI 界面。
数据观测：环境看板，实时展示温度、湿度、空气质量等数据，支持历史曲线。
服务中心：耗材管理，依据设备运行时间 / 传感器数据计算耗材寿命并自动提醒；服务预约，提供一键报修 / 保养预约入口，对接工单系统或预留接口。
（二）云服务平台（Backend - SaaS）
核心职责：设备管理、规则编排、运维监控。
设备接入：物模型定义，标准化设备属性、事件、服务功能，实现多协议设备归一化管理。
规则引擎：可视化逻辑编辑器，支持 IF-THEN 逻辑配置与模版保存。
云边协同：支持云端编辑控制逻辑，通过 OTA 远程下发 / 同步至边缘网关本地运行。
运维中心：健康大屏展示设备在线率、故障告警；远程预诊断可查看电压、水流、压力等底层数据，实现上门前故障定位。
（三）边缘侧与硬件接入
核心职责：协议转换、断网执行、数据清洗。接入设备及协议要求：
主机：3 种协议
新风除湿机：3 种协议
主机控制模块：1 种协议
温控器：1 种协议
生活热水控制器：1 种协议
混水控制器：待定，预留 485 / 透传接口
分集水器控制器：待定，8 路通断器，支持状态反馈
四、双方职责界定（SOW）
1. 基础设施
甲方：购买云服务器、域名，提供测试样机。乙方：服务器环境部署、数据库搭建。交付标准：系统在甲方服务器成功运行。
2. 移动端开发
甲方：提供 UI 设计风格指引，申请上架账号。乙方：iOS/Android 双端开发、协助上架、短信服务对接。交付标准：App Store / 应用宝审核通过；局域网控制延迟 < 200ms。
3. 云平台开发
甲方：提供核心控制逻辑说明。乙方：规则引擎开发、物模型定义、管理后台开发。交付标准：支持逻辑在线编辑并下发生效。
4. 嵌入式 / 边缘
甲方：提供设备协议文档。乙方：协议解析驱动开发。交付标准：所有清单内设备数据准确上云。
五、UI 界面设计
（一）移动端页面
1. 首页（Home）- 全局驾驶舱
顶部状态与天气看板：自动定位、室外温度、天气图标、AQI、PM2.5、室外湿度展示，背景随天气变化。
房产信息卡片：显示当前住宅名称，点击切换多房产。
全局系统模式：制冷、制热、通风三段式互斥按钮，切换需二次确认。
室内环境指数：室内平均温度、湿度、CO₂浓度，CO₂按浓度变色（<800 绿色，>1000 黄色）。
智能场景：会客、离家、睡眠、ECO、度假模式；度假模式需选择返程日期时间，系统自动预冷 / 预热。
2. 冷暖（Climate）- 三级精细调控
视图切换：首页（全屋）、楼层、区域无刷新切换。
全屋视图：统一设定全屋温度、湿度，覆盖房间独立设定。
楼层视图：楼层一键开关，显示温控器开启数量、新风运行状态。
区域视图：房间启停、温度设定；顶面 / 地面辐射开关；新风微控（CO₂阈值、湿度、风速）。
3. 水系统（Water）- 循环与净化
热水循环：显示当前水温，支持全天、定时、临时、关闭循环，支持热力杀菌时间预约。
全屋净水：滤芯状态可视化，寿命 < 10% 变红，支持预约更换。
4. 我的（Profile）- 服务与维保
用户信息：头像、昵称、身份标识、通知中心。
项目概述：五恒系统技术介绍富文本。
预约保养：显示上次保养时间，支持服务类型选择与快速预约。
关于新宜能：品牌介绍、客服电话、版本号、隐私条款。
（二）iPad 端
功能与手机端一致，适配大屏展示。
